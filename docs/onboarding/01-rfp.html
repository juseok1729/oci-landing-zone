읽기 전에 (신입용 안내)

RFP 는 고객이 "무엇을" 원하는지 적은 문서이고, 제안서는 수행사가 "어떻게" 할지 적은 문서다. 수주 후에는 RFP 의 요구사항이 계약 범위가 되므로, 적혀 있지 않은 일은 하지 않아도 되고 적혀 있는 일은 반드시 해야 한다.

요구사항 ID (e.g., SFR-005) 는 제안서 → 요구사항 추적표 → 설계서 → 시험 결과서까지 따라가는 추적 키다. 검수는 ID 하나하나가 충족됐는지 확인하는 방식으로 진행된다.

처음 읽을 때는 세 곳을 먼저 본다: 1.4 의 범위 밖 (하지 않는 일), 3.2 의 제약사항 (COR) (하면 안 되는 일), 5장의 평가 배점 (고객이 중요하게 여기는 일).

1.2 추진 배경

  • 장비 노후: 이커머스와 ERP 는 본사 전산실에서 운영 중이며, 서버 · 스토리지 도입 후 7년이 지나 유지보수 종료가 예정돼 있다.
  • 트래픽 변동: 대형 프로모션 기간에 접속이 평시의 5배까지 늘어 응답 지연과 주문 실패가 반복됐다. 장비를 피크 기준으로 사면 평시에는 대부분 놀게 된다.
  • 운영 · 개발 혼재: 개발 서버가 운영과 같은 네트워크에 있어, 개인정보 보호 점검에서 "운영 · 개발 환경 분리 미흡" 지적을 받았다.
  • 보안 체계 분산: 방화벽이 단일 장비이고 웹 방화벽 · DB 접근제어가 없어, 시스템마다 보안 수준이 다르다.

1.3 사업 목적

  1. 이커머스 · ERP 를 OCI 로 전환해 트래픽에 맞춰 늘고 주는 인프라를 갖춘다.
  2. Hub & Spoke 구조로 인터넷 출입구와 보안 장비를 hub 하나로 모아, 시스템이 늘어도 보안 정책을 한 곳에서 관리한다.
  3. 운영 · 개발을 네트워크 단위로 분리하고 개인정보 보호 법령의 기술적 보호조치를 충족한다.
  4. 발주기관 인력이 직접 운영할 수 있도록 설계 문서, 운영 매뉴얼, 코드화된 구성을 넘겨받는다.

2.3 설계 원칙

  • 인터넷 출입구는 하나: 인터넷 출입은 hub 의 방화벽을 거친다. spoke 에는 IGW · NAT gateway 를 두지 않는다.
  • OCI 서비스는 spoke 마다: spoke 는 각자 SGW 로 Object Storage 같은 OCI 서비스에 나간다. OCI 가 요청이 어느 VCN 에서 왔는지 구분하므로 VCN 별 접근 제어를 할 수 있고, hub 경로의 장애가 번지지 않는다.
  • 운영 ↔ 개발 차단, 관리망은 전체 접근: 관리 VCN 의 모니터링 · 접근제어 · DB 암호화 서버는 모든 VCN 에 닿아야 한다.
  • 업무 단위 compartment: HUB, E-COMMERCE, ERP, MGMT 로 나눠 권한과 비용을 업무별로 본다.
  • 관리형 서비스 우선: DB, Cache, LB 는 OCI 관리형 서비스를 먼저 검토하고, 직접 운영하는 서버를 줄인다.
  • 늘릴 자리를 남긴 주소: VCN 은 /16, subnet 은 세 번째 옥텟을 16 단위로 잡아 /20 까지 제자리 확장할 수 있게 한다.

2.5 주요 트래픽 흐름

흐름경로와 통제
고객 → 온라인몰인터넷 → hub 외부 LB → WAF → 방화벽 → DRG → ec-prd 내부 LB → WEB. 웹 공격은 WAF, 그 밖의 통제는 방화벽이 맡는다.
spoke → 인터넷spoke 기본 경로 → DRG → hub → 방화벽 (SNAT) → IGW. 외부에서 보이는 주소는 방화벽의 공인 IP 하나다 (PG · 택배 API 의 허용 IP 등록에 쓴다).
운영 ↔ 개발DRG → hub → 방화벽에서 차단. 이커머스 운영 ↔ ERP 운영은 허용 (주문 · 정산 연동).
관리 → 전체mgmt 에서 모든 VCN 으로 허용 (모니터링, DB 접근제어, DB 암호화, 배포).
본사 ↔ 클라우드IPSec VPN → DRG → hub → 방화벽 → 대상 VCN. ERP 사용자 접속과 관리자 접속에 쓴다.
spoke → OCI 서비스spoke 의 SGW → Object Storage 등. hub 와 방화벽을 거치지 않아 백업 · 로그 같은 대용량 트래픽이 방화벽 성능을 쓰지 않는다.

3.2 상세 요구사항

시스템 장비 구성 (ECR)

ID명칭내용
ECR-001리전 · 가용성OCI 서울 리전을 쓴다. 운영 서버는 2대 이상을 서로 다른 fault domain 에 둔다.
ECR-002이커머스 자원운영: WEB 2~6대 (자동 확장, 2 OCPU · 16GB 기준), ADMIN 2대, Cache 2노드, MySQL HA (4 OCPU). 개발: WEB 1대, ADMIN 1대, Cache 1노드, MySQL 단일 (2 OCPU).
ECR-003ERP 자원운영: AP 2대 (4 OCPU · 32GB), DB HA (8 OCPU). 개발: AP 1대, DB 단일 (2 OCPU).
ECR-004공통 · 보안 자원방화벽 2대 (Active-Passive), WAF 2대 (Active-Active) 와 외부 LB, bastion, 모니터링 서버, CI/CD 서버, DB 접근제어 · DB 암호화 서버.
ECR-005자원 산정 근거제안사는 ECR-002~004 를 현행 사용량과 피크 트래픽으로 다시 산정해 근거와 함께 제출하고, 월 클라우드 사용료 추정치를 포함한다.

기능 (SFR)

ID명칭내용
SFR-001compartment · IAMHUB, E-COMMERCE, ERP, MGMT compartment 를 만들고, 역할별 그룹에 최소 권한 정책을 준다. 발주기관이 지정한 상위 compartment 아래에만 만든다.
SFR-002Hub VCN방화벽 untrust · trust · mgmt · HA, WAF, DNS subnet 을 둔다. IGW 는 hub 에만 둔다.
SFR-003Spoke VCN업무별 VCN 5개를 만들고 계층별 subnet (LB · WEB · ADMIN · CACHE · DB) 을 private 으로 둔다. 기본 경로는 DRG 로 보내고, OCI 서비스용 SGW 를 VCN 마다 둔다.
SFR-004DRG 라우팅spoke 끼리 직접 통신하지 않고 모든 spoke 트래픽이 hub 를 거친다. spoke 를 추가할 때 기존 spoke 의 설정은 바꾸지 않는다.
SFR-005방화벽 (NVA)이중화하고, spoke 의 인터넷 출구를 단일 공인 IP 로 SNAT 한다. zone 기반 정책으로 운영 ↔ 개발을 차단하고 관리 VCN 은 전체 허용한다.
SFR-006웹 방화벽 (WAF)온라인몰 인바운드 경로에 이중화해 두고, OWASP Top 10 유형의 공격을 탐지 · 차단한다. 인증서 갱신 절차를 포함한다.
SFR-007본사 VPNOCI 와 본사를 IPSec VPN (터널 2개) 으로 잇는다. 본사 장비 설정은 발주기관이 하고 수행사는 설정값을 제공한다.
SFR-008DNS본사와 OCI 사이에서 서로의 내부 이름을 해석할 수 있게 hub DNS subnet 에 resolver endpoint 를 둔다.
SFR-009이커머스 인프라외부 LB → WAF → 내부 LB → WEB (자동 확장) → Cache · DB 구조로 만든다. ADMIN 은 본사 대역에서만 접근한다.
SFR-010ERP 인프라인터넷에 노출하지 않고 본사 VPN 으로만 접속한다. 이커머스 운영과 주문 · 정산 연동 경로를 둔다.
SFR-011관리 인프라bastion (접속 경로 단일화), 모니터링, CI/CD, DB 접근제어, DB 암호화 서버를 관리 VCN 에 둔다.
SFR-012로그 수집VCN flow log, 감사 로그, 서버 syslog 를 업무별 Object Storage 버킷으로 모은다. 버킷은 공개 접근을 막는다.
SFR-013모니터링 · 알림자원 사용률, 서비스 상태, 방화벽 · VPN 상태를 수집하고 임계치를 넘으면 메일 · 메신저로 알린다.
SFR-014백업DB 자동 백업 (보존 30일 이상), 부트 볼륨 백업 정책, 복구 절차서를 만들고 복구 시험을 한 번 이상 한다.

성능 (PER) · 인터페이스 (SIR)

ID명칭내용

PER-002자동 확장WEB 은 최소 2대, 최대 6대로 자동 확장하고, 확장 판단부터 서비스 투입까지 10분 이내다.
PER-003방화벽 처리량피크 트래픽의 2배 이상을 처리할 수 있어야 하며, 성능 시험으로 증명한다.
SIR-001본사 연계본사 사용자는 VPN 으로 ERP 와 관리 화면에 접속한다. 본사 대역은 192.168.10.0/24 다.
SIR-002외부 API 연계PG (결제대행), 택배 조회, 본인인증 API 로 나가는 트래픽은 공인 IP 하나로 나간다. 이 IP 가 바뀌면 상대 기관에 미리 알린다.
SIR-003이커머스 ↔ ERP운영끼리 (주문 · 매출 · 재고), 개발끼리 연동을 허용하고 필요한 포트만 연다. 운영 ↔ 개발 교차 연동은 막는다.

데이터 (DAR) · 테스트 (TER)

ID명칭내용
DAR-001데이터 이관이커머스 DB (약 500GB), ERP DB (약 1TB), 상품 이미지 (약 2TB, Object Storage 로) 를 옮긴다. 리허설 2회 이상, 건수 · 체크섬으로 정합성을 검증한다.
DAR-002보존 기간「전자상거래법 시행령」 제6조의 거래기록 보존 기간 (표시 · 광고 6개월, 계약 · 청약철회 5년, 대금결제 · 재화공급 5년, 불만 · 분쟁처리 3년) 을 지킬 수 있는 저장 구조와 수명주기 정책을 둔다.
DAR-003복구 목표운영 DB 는 RPO 1시간, RTO 4시간 이내로 복구할 수 있어야 한다 (시점 복구 포함).
TER-001통신 시험2.5 의 흐름마다 허용과 차단을 모두 시험한다 (e.g., 운영 → 개발이 실제로 막히는지).
TER-002성능 시험PER-001~003 을 부하 시나리오로 시험하고 자동 확장 동작을 기록한다.
TER-003장애 시험방화벽 · WAF 절체, DB failover, fault domain 장애를 가정해 시험하고 절체 시간을 잰다.
TER-004취약점 점검오픈 전에 인프라 취약점 점검과 외부 전문기관의 모의해킹을 받고, 조치 결과를 제출한다.

보안 (SER)

ID명칭내용
SER-001법령 준수「개인정보 보호법」과 「개인정보의 안전성 확보조치 기준」 (개인정보보호위원회 고시) 의 기술적 보호조치를 충족한다.
SER-002접근통제개인정보처리시스템 접속을 IP 등으로 제한하고, 외부에서 접속할 때는 OTP 같은 안전한 인증수단을 쓴다 (고시 제6조). DB 접속은 DB 접근제어를 거친다.
SER-003암호화고시 제7조 대상 (주민등록번호, 여권번호, 운전면허번호, 외국인등록번호, 신용카드번호, 계좌번호, 생체인식정보) 은 암호화해 저장하고, 비밀번호는 일방향 암호화한다. 인터넷 구간은 TLS 로 보낸다.
SER-004접속기록개인정보처리시스템 접속기록을 2년 이상 보관한다 (5만 명 이상 처리 시스템, 고시 제8조). 위 · 변조를 막도록 보존 규칙을 건 저장소에 둔다.
SER-005계정 · 권한개인별 계정, 최소 권한, 관리자 MFA 를 적용하고, 권한 부여 · 변경 · 말소 내역을 3년 이상 보관한다 (고시 제5조).
SER-006네트워크 보안관리 포트 (SSH, 관리 GUI) 를 인터넷에 열지 않고 본사 · bastion 에서만 접근한다. 기본 security list 의 전체 허용 규칙을 정리한다.
SER-007클라우드 보안 설정Cloud Guard 등 OCI 보안 서비스 적용을 검토하고, 버킷 공개 접근 금지와 감사 로그 보존을 설정한다. 업무별 버킷은 IAM network source 로 해당 업무 VCN 에서만 접근하게 한다.

품질 (QUR) · 제약사항 (COR)

ID명칭내용
QUR-001가용성운영 서비스 월 가용률 99.9% 를 목표로 단일 장애점을 없앤다 (계획 정지 제외).
QUR-002문서 품질산출물은 발주기관 양식을 따르고, 설계서의 값과 실제 구성이 일치함을 구성 점검표로 증명한다.
QUR-003구성 코드화네트워크 · 보안 · 서버 구성은 코드 (e.g., Terraform) 로 관리해 같은 구성을 다시 만들 수 있게 한다.
COR-001작업 범위발주기관이 지정한 상위 compartment 아래에서만 작업한다. 그 상위와 다른 compartment 의 리소스는 바꾸거나 지우지 않는다.
COR-002변경 통제운영 오픈 후 모든 변경은 변경 요청서 승인 뒤에 한다. 콘솔에서 수동으로 바꾸지 않고 코드로 바꾼다.
COR-003보안 서약투입 인력은 보안 서약서를 낸다. 계정 · 비밀번호 · 키를 공유하지 않고, 산출물을 외부로 가져가지 않는다.
COR-004제품 중립이 RFP 는 특정 제품을 지정하지 않는다. 제안사는 요구사항을 충족하는 동등 이상의 제품을 제안한다.

프로젝트 관리 (PMR) · 지원 (PSR)

부록. 용어 정리

용어뜻
Hub & Spoke공용 장비 (방화벽, 게이트웨이) 를 hub 에 모으고 업무 네트워크 (spoke) 는 hub 를 거쳐서만 밖과 서로에게 닿게 하는 구조
VCNOCI 의 가상 네트워크. 하나의 CIDR 범위를 갖고 subnet 으로 나눈다.
compartmentOCI 리소스를 묶는 논리 폴더. 권한 정책과 비용 집계의 단위다.
DRGDynamic Routing Gateway. VCN, VPN, 전용회선을 잇는 가상 라우터. DRG route table 로 attachment 사이 경로를 정한다.
IGW · SGWInternet Gateway (인터넷 출입), Service Gateway (인터넷을 거치지 않고 Object Storage 같은 OCI 서비스로 가는 문)
NVANetwork Virtual Appliance. VM 으로 동작하는 방화벽 · 라우터 (e.g., 상용 방화벽 VM, VyOS)
WAFWeb Application Firewall. SQL injection 같은 웹 공격을 막는 장비
SNAT내부 주소를 공인 IP 로 바꿔 내보내는 것. spoke 가 인터넷으로 나갈 때 방화벽이 한다.
fault domain같은 가용 영역 안에서 하드웨어를 나눠 둔 단위. 서버를 서로 다른 fault domain 에 두면 장비 하나의 장애가 서비스 전체를 멈추지 않는다.
RPO · RTORPO 는 장애 때 잃어도 되는 데이터의 시간 범위, RTO 는 복구까지 걸려도 되는 시간
A-P · A-AActive-Passive (한 대만 처리하고 한 대는 대기), Active-Active (두 대가 나눠 처리)
PGPayment Gateway. 카드 결제를 대행하는 회사. 보통 접속하는 쪽의 공인 IP 를 미리 등록받는다.
